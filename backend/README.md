# CampusSphere backend

Modular Express + TypeScript API using PostgreSQL and Prisma. API routes are versioned under `/api/v1`.

## Setup

1. Install Node.js 20 or newer and PostgreSQL 16 or newer.
2. Copy `.env.example` to `.env`, then set real database and JWT values.
3. Run `npm install`.
4. Run `npm run db:generate` and `npm run db:migrate`.
5. Run `npm run dev`.

Health check: `GET http://localhost:4000/api/health`

## API overview

All product routes are under `/api/v1`. Protected routes require an `Authorization: Bearer <access-token>` header. Authentication also sets an HTTP-only refresh cookie.

- `/auth` - register, login, logout, refresh, and current user.
- `/users`, `/connections` - profiles and connection requests.
- `/communities`, `/posts` - communities, membership, feed, likes, and comments.
- `/events`, `/projects`, `/opportunities` - campus activities and discovery.
- `/notifications`, `/conversations` - notification and persisted messaging APIs.
- `/search`, `/dashboard` - grouped search and personalised dashboard data.
- `/academic` - student academic enrollment data, assignment-scoped teacher data, admin summaries, and an optional development-only role assignment endpoint.

New public accounts always receive the `STUDENT` role. To test teacher/admin routing locally, set a private 32+ character `DEV_ROLE_ASSIGNMENT_KEY` and call the authenticated development endpoint with the matching `x-dev-role-key` header. The endpoint returns 404 in production and when the key is not configured.

## Verification

Run `npm run build` for TypeScript validation, `npm run test` for automated tests, and `npm audit --omit=dev` for the dependency audit. Do not commit `.env`; it is ignored by the repository.

`npm run db:seed` is intentionally a no-op. CampusSphere does not ship demo users or fake product data.

### Database safety for verification

- Never create verification users, projects, or other fixtures in the normal development database.
- Database-backed automated tests must use a dedicated `TEST_DATABASE_URL` whose database name ends in `_test`. Test setup must refuse to run if it resolves to the normal `DATABASE_URL`.
- Create each test's records inside a transaction that is rolled back, or delete the complete fixture graph in `afterEach`/`finally` cleanup.
- Manual browser verification should use the three existing development accounts. If temporary data is unavoidable, record its IDs and remove it in the same verification run.
- Unit tests that do not need PostgreSQL should continue using mocks or pure validators and must not connect to the development database.

## Profile and account settings

Apply committed migrations with `npm.cmd run db:deploy` and regenerate the client with `npm.cmd run db:generate` before starting an updated checkout. The profile-cover migration adds nullable columns only; it does not replace existing accounts or profile data.

| Endpoint | Behavior |
| --- | --- |
| `GET /users/me/settings` | Returns complete notification, privacy, and appearance defaults merged with saved preferences. |
| `PATCH /users/me/settings` | Accepts one or more complete preference sections; rejects null bodies, unknown sections, invalid values, and empty updates. |
| `POST /users/me/avatar` | Multipart `avatar`, JPEG/PNG/WebP, at most 5 MB. |
| `POST /users/me/cover` | Multipart `cover`, JPEG/PNG/WebP, at most 8 MB. |
| `DELETE /users/me/cover` | Clears the cover and removes its managed local file. |
| `POST /auth/change-password` | Requires the current password and a different new password of at least eight characters; rate limited. Google-managed accounts continue using Google sign-in. |

All these routes require authentication and use the session user, never a client-supplied user ID. Uploads check their image signature against the supplied MIME type and remove new files on validation or database failure. An older image is removed only after its replacement is saved.

Discovery paginates in PostgreSQL with matching privacy filters for the result and total count. Private and connections-only profiles are excluded as appropriate; hidden details cannot be used as discovery search or filter matches. Profile activity visibility is also enforced in post feeds, profile posts, comments, and dashboard activity. Related member cards redact the hidden college, course/year, and skill fields.

Messages require an accepted connection or collaboration. The connections-only option is checked both when opening a direct conversation and when sending in an existing conversation. Notification switches control optional notification records for messages, connections, social reactions, community discussions, event changes/cancellations, and opportunity/project applications. Switching message notifications off does not stop delivery of the message itself. Scheduled event reminders are not generated by this API.

Appearance defaults to light mode with the CampusSphere orange brand accent. Legacy accent values remain readable. Password changes clear refresh sessions; previously issued access tokens retain their existing 15-minute expiry.

HTTP and Socket.IO use the same frontend origin configuration: `FRONTEND_URL`, plus the local Live Server addresses outside production. Temporary tunnel hostnames are not hardcoded.

The unit-test configuration provides fake signing and database settings. Tests use mocked persistence and temporary upload files; they do not create accounts or alter the development database.
